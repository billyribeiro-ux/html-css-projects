Scroll-Driven Animations: animation-timeline: scroll()

Eliminating main-thread scroll jank. By binding CSS keyframe animations directly to the browser compositor's scroll timeline, reading indicators and dynamic sticky navigations execute at a native 120fps with zero JavaScript.

I. The Problem with JavaScript Scroll Listeners & INP

For over two decades, implementing sticky header shrink effects or reading progress bars required attaching event listeners to window.addEventListener('scroll'). Even with requestAnimationFrame or passive event flags, continuous DOM reads (scrollTop, getBoundingClientRect()) routinely cause layout thrashing, elevate the browser's Interaction to Next Paint (INP) metric above Google's 200ms threshold, and drop frames during rapid touchpad or momentum scrolling.

II. Compositor-Driven Scroll Timelines

CSS Scroll-Driven Animations transfer the calculation from the browser's JavaScript main thread directly to the compositor thread. By specifying animation-timeline: scroll(), the animation progress is normalized between 0% and 100% corresponding to the scrollable scroll-port.

Architectural & SEO Takeaway

The compositor can advance the transform and opacity of the header and progress bar during smooth kinetic scrolling even if the JavaScript event loop is temporarily blocked by heavy background data parsing, ensuring flawless Core Web Vitals scores.

III. Practical Applications in Enterprise Systems

From high-frequency financial dashboards monitoring trading logs to technical API reference portals, scroll-driven timelines allow developers to link table-of-contents highlights, sticky floating action bars, and subtle shadow elevations seamlessly to document progression.
